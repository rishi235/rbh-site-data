FINDING 2 (fault in this run's own work). The first negative test for a
foreign ODS code replaced FWK18 with another branch's code and did not fire.
The mutation was a no-op: FWK18 appears nowhere in the 12 pages. Re-tested by
INJECTING a foreign ODS code instead of substituting one, which fires on all
12. The same fault hid inside the widget test twice over: the first mutation
substituted a widget id that is not on any page, and the replacement injected
a FABRICATED id, which correctly did not fire because the scan compares
against real branches.json values only. It fires once a genuine foreign id
(Cherry Lane's pharmacyFirst diary) is injected. Testing a scan by corrupting
a token the page does not contain proves nothing, and it looked exactly like
a passing test.

FINDING 3 (fault in this run's own work). The sheet script initially flagged
the insect bite description at 164 characters as over-length. It is not. The
house limit is DESC_MAX = 165 in tools/check-seo-lengths.js, set deliberately
with a written rationale, and 160 was this script's own invention. The page is
correct and the script was wrong. Corrected before the pass was recorded.

FINDING 4 (checked, correctly out of scope, no action). Nine paste sheets
carry a literal U+2014 EM DASH in their "## Brand - Town - Service" headings,
while check-em-dashes.js passes. That is not a hole. The checker's rule is
scoped in its own header to PASTEABLE VALUES, the Page Title, Page
Description, Meta Keywords, SEO title and SEO description lines that get typed
into Weebly. A sheet heading is a structural label that is never pasted
anywhere, so it is correctly outside the rule. Recorded because a future pass
reading the raw sheets will see the same dashes and should not re-raise it.
