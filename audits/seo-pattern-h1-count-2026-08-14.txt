THE DEFECT
==========
Item 3.2 is "put the town and service words into every page title,
description and HEADING". Every heading rule in the repo reads the FIRST h1
and stops:

  - check-seo-pattern.js  exact match      /<h1>([\s\S]*?)<\/h1>/  .exec, first only
  - check-seo-pattern.js  checkH1()        handed that same single string
  - check-seo-pattern.js  checkCrossTown() handed that same single string
  - check-seo-lengths.js  rule 4           /<h1[^>]*>([\s\S]*?)<\/h1>/i .exec, first only

Not one of them counts. A second h1 was therefore invisible to all four at
the same time, and the four are the whole of the repo's heading cover.

This is not cosmetic on THIS item. The cross-town ABSENCE rule was added on
the 2026-08-11 pass on item 3.2 precisely because Scorah Bramhall and Hazel
Grove share a domain, and a page naming its sister town makes the two
compete for one catchment instead of each owning its own. A second h1 was
the one place that rule could not look.

"Exactly one h1 per page" was verified BY HAND on the 2026-08-11 pass and
re-verified by independent extraction on 2026-08-12 and 2026-08-13. It was
true all three times and no rule preserved it. Same fault this file's own
CROSS-TOWN note records: a hand check that no rule replaces is a check that
holds until the next regeneration.

THE FIX
=======
tools/check-seo-pattern.js: new ONE H1 rule. Every typed page must carry
exactly one h1. Counting uses <h1[^>]*> so an h1 that gains an attribute
still counts. The rule runs BEFORE the content rules, because those rules
all read a single h1 and would otherwise report on the first while the
second went unread.

The exact match deliberately KEEPS its bare <h1> read rather than being
widened to match the counting pattern. The two ask different questions: an
attributed h1 should fail loudly at the exact match rather than be quietly
accepted, and neither rule is loosened to suit the other. Negative test 5
below holds that line.

Summary line added:
  one-h1 rule: 177 pages carry exactly one h1, so the pattern, seoTown,
  service-word and cross-town rules read the whole heading of every page.

RESIDUAL, STATED PLAINLY
========================
The rule counts h1 OPENING tags. A malformed page with one opening tag and
no closing tag counts as 1 here and fails elsewhere: the exact match reads
to the next </h1> and would not find its expected string. Not treated as a
live gap, but recorded rather than left implicit.

check-seo-lengths.js rule 4 still runs its own single .exec() to read the H1
for its uniqueness comparison. That is now safe rather than lucky, because
this rule guarantees there is only one h1 to read, and the two checkers run
in the same suite. Recorded as a dependency between the two files.
