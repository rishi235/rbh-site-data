WHY A CHARACTER TEST COULD NEVER HAVE CAUGHT IT
An em dash is one code point and an emoji is one, so "is this file ASCII" is
a decidable property of the bytes. "Organized" is pure ASCII, correctly
spelled, and an ordinary English word. It is wrong only because it is the
wrong side of the Atlantic, which is knowledge and has to be listed.

PART 3 - THE FIX: tools/check-uk-spelling.js (NEW, the 33rd checker)
===========================================================================
The danger with a word list is that it becomes useless, not that it becomes
weak. Measured before writing a line of the checker, over the same 233 files:

    \bcolor\b   614 hits in 187 files, every one CSS (color:#fff)
    \bcheck\b   346 hits, every one "free NHS blood pressure check", which
                is the correct UK name of a service this estate sells
    \bcenter\b   51 hits, every one text-align:center
    \bmath\b     15 hits, every one Math.ceil
    behavior      1 hit, scrollIntoView({behavior:"smooth"})

So the checker is narrowed in TWO independent directions.

1. THE READER ONLY EVER SEES COPY
   .html/.txt   text nodes, plus alt, title, aria-label, placeholder and
                meta/og content. script and style dropped whole, every
                other attribute dropped with its tag.
   .js          string literals only, comments blanked first.
   .css         the value of content: and nothing else.
   .md          whole file, less fenced code, less URLs, less quoted spans.
   branches.json string values, less URLs. Read because modules/emar/emar.js
                renders branch fields straight onto the live page and some
                of them reach no .html file in this repo.

   The hard part was .js, and it took three attempts. A string literal here
   is usually PART of a tag, because the markup is built by joining literals
   with +, so a literal can sit entirely inside a tag with neither "<" nor
   ">" in it to key on:

       "Call <a href='" + telHref + "' style='color:#fff;font-weight:700;" +
         "text-decoration:underline;'>" + name + "</a>"

   The second literal is pure CSS. A regex over one literal cannot see it.
   The checker now carries tag state ACROSS the literals of a file in source
   order, which is the order the browser joins them in. "<" only opens a tag
   when a letter or "/" follows, the real HTML rule, so ordinary copy such as
   "blood pressure < 140" stays readable. A tag left open at end of file is
   reported as a finding, because otherwise it would silently blank the rest.

2. THE LIST ONLY HOLDS WORDS WITH NO LEGITIMATE UK READING
   167 US spellings against their UK forms. Excluded on purpose, each named
   in the file with its reason: check, meter, license, practice, program,
   curb, story, disk, tire, inquiry, math, fetus, sulfur, judgment. fetus
   and sulfur are the spellings UK medical usage and the BNF actually use.
   Vocabulary (drugstore, vacation, shot, refill) is out of scope: it needs
   a sense of register, not a word list. Named so the omission is a decision.

   The list also guards itself: an entry mapping to itself fails, an entry
   that is both a flagged US form and another entry's UK fix fails, and the
   list may not shrink below a floor of 120.

   Third rule: the reader must have read something. A file class opened and
   yielding no copy at all fails rather than passing. That is the fault this
   repo has now found six times.
