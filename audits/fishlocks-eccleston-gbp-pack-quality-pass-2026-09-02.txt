Root cause: the address-line presence rule (added by the item 4.10 pass,
2026-08-14) and the post-town rule (added by the item 3.5 pass, 2026-08-13)
both predate streetPattern() (added by the item 1.2 eighth pass, 2026-09-01)

and the FOREIGN-street sister rule two blocks above already tolerate
Road/Rd, Street/St, Lane/Ln, Drive/Dr and Avenue/Ave abbreviations since that
same 1.2 pass; the address-line-specific rule and its post-town dependent had
not been carried across, so the single line a paster actually sets the
Google Maps pin from was stricter than the rest of the file, and would
hard-fail the whole checker on a correctly-written, merely abbreviated
address.

Fix: added lastStreetMatch(street, haystack), a thin wrapper that reuses
streetPattern()'s source with a global flag and returns the last match (or
null), preserving the original lastIndexOf-based semantics but abbreviation-
aware. The address-line presence check now tests for a match rather than an
indexOf hit; the post-town calculation now takes its start index and matched
length from that same match object instead of assuming the match is exactly
ownStreet.length characters long (needed because "St" is shorter than
"Street"). Dated comments added at both the helper and the two call sites.
