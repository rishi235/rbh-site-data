Two PowerShell authoring mistakes caught before they became false results, kept
here as a method note: an early attempt used the `-replace` operator with a
three-way comma-separated argument list (pattern, replacement, count), which
PowerShell parses as an array literal for the replacement operand rather than a
count parameter - the resulting write produced a zero-byte file, caught
immediately by SHA256 mismatch (hash of an empty file) rather than trusted as a
real edit. A second attempt used string index arithmetic to insert before
"</body>" in the switch page, which does not contain that tag (it is a Weebly
embed fragment, not a full document) - IndexOf returned -1, and the resulting
Substring call again produced a zero-length result, again caught by SHA256
before being mistaken for a real injection. Both fixed by switching to a
simple append/whole-string [regex]::Replace with an explicit "modified longer
than original" guard before every write.
