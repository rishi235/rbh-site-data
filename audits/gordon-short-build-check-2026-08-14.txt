THE GAP: THE SYMPTOMS BLOCK WAS READ BY NOTHING
Every Pharmacy First condition page carries three blocks of clinical copy
answering three different questions:

  1. "Do I have this?"        -> CONDITIONS[cond].symptoms
  2. "Is the service for me?" -> CONDITIONS[cond].eligibleYes and ageNote
  3. "What if it is not?"     -> CONDITIONS[cond].eligibleNo

Block 2 has been guarded since run 63 by check-pharmacy-first-eligibility.js.
Block 3 has been guarded since run 140 by check-pharmacy-first-safety-net.js,
written on this same item's third pass. Nothing had ever read block 1.

It was found by method rather than by eye: all 66 distinct headings across the
12 Gordon Short pages were extracted and each generic phrase was searched
across every file in tools/. 26 came back with no checker mentioning them, and
the seven "<condition> symptoms" headings were the only clinically loaded
group among them. The symptoms list is composed once in build-service-pages.js
and rendered onto 98 live condition pages, 7 pathways across 14 branches. It
is the first clinical block a patient reads and the one they self-assess
against. A bad edit there does not break a page; it makes the page quietly
describe the wrong illness while all 33 existing checkers stay green.

NEW: tools/check-pharmacy-first-symptoms.js, 8 rules plus three coverage
guards and a two-way pin guard on PATHWAYS.

  rule 1  presence: a ready pathway with no symptoms array, fewer than 3
          points, or a blank point
  rule 2  no duplicated symptom within a pathway
  rule 3  the block is on the page: composed heading "<longName> symptoms"
          and the shared lead "Common signs include:"
  rule 4  every own symptom point present verbatim as an ITEM OF THE LIST
  rule 5  the list holds exactly as many items as the generator declares
          (rule 4 catches a point that went missing, rule 5 one that was
          added by hand)
  rule 6  no other pathway's symptom in the list and no other pathway's
          symptoms heading on the page
  rule 7  descriptive not directive: no GP, NHS 111, 999, A&E, walk-in or
          urgent-care route inside a symptom point, because escalation
          belongs in the safety net where the safety-net checker reads it
          and enforces the "call 999" wording
  rule 8  no medicine from tools/pom-names.js named in a symptom point
          (82 names read from that file rather than mirrored into a literal)

14 negative tests, all 14 caught their break, every injected file restored

A DEFECT IN THE CHECKER, FOUND BY ITS OWN FIRST RUN AND FIXED BEFORE COMMIT
The first draft read whole-page text with substring matching, and rule 6
failed on 28 clean pages. "A high temperature" is a genuine sore throat and
earache symptom; it is also a substring of the sinusitis symptom "A high
temperature or feeling generally unwell", and it appears again inside the UTI
safety net's kidney-infection line. The eligibility, safety-net and FAQ blocks
legitimately reuse this vocabulary, so a symptoms rule that reads them cannot
be right. Rules 3 to 6 now read the symptoms block only and compare whole
values, never substrings, which is both correct and stricter. This is the
fourth time this repo has found the same fault: when a checker fires, or
passes, ask WHICH TEXT it read.
