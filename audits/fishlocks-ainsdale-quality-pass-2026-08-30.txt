Recommended design for whoever picks this up next, so it does not have to
be re-derived: because both tile strings are static literals (not spliced
per branch the way the weight loss RULE 11 template lines are), a full
RULE-11-style per-branch template resolver is not needed. A lighter rule
in each checker is enough:
 1. Read the tile's literal blurb straight out of
    build-branch-landing-pages.js (the same "read the copy out of the
    generator" approach every rule in both checkers already uses).
 2. Verbatim-check it appears on every branch landing page in
    modules/branch/pages (a page cannot drift from the generator).
 3. Run the blurb text through the same pattern sets these checkers
    already import for their own leaf pages: pom-names.js (medicine
    names), outcome-promise-patterns.js (no protection/results claim),
    and the local funding/stock hedge patterns already defined in
    check-travel-clinic-copy.js.
This is materially smaller than RULE 11 because there is exactly one
string per service to check, not one resolved per branch, and it can be
proved clean against the current copy in the same run that adds it.
Left for a dedicated pass rather than added here, because a change to a
regulated-copy checker deserves the same negative testing RULE 11 got (17
cases) rather than being fitted in alongside a routine quality pass.
