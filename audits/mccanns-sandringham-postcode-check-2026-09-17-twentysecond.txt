INCIDENTAL FINDING: L20 5DW is not, in fact, an unnarrated value - a follow-up
sweep of every live branch's own postcode against the narrative files found
all sixteen are already quoted between 13 and 72 times each in AGENT_LOG.md and

TEST 2 (isolate message 1, and prove self-reference does not count as a
quote): restored the checker to the pre-TEST-1 baseline (sha256-verified),
then added a NARRATIVE_POSTCODES key, "ZZ98 8ZZ" - a fabricated, non-branch
postcode, confirmed by repo-wide grep to occur nowhere else in the repository

  STALE    NARRATIVE_POSTCODES names ZZ98 8ZZ but no narrative file quotes
           it. Remove the entry.

This confirms two things at once: the message fires correctly when a key is
genuinely unquoted, and the checker's own self-exclusion
(`if (isNarrative && r !== SELF) ...` at line ~615) works as designed - the
key's own appearance inside tools/check-postcodes.js's source text (a
NARRATIVE_FILE) does NOT count towards narrativeQuotes, exactly as the
header comment above the NARRATIVE_POSTCODES block states ("this file is
itself scanned and is itself a narrative file, so writing a value into
NARRATIVE_POSTCODES made that value appear in the repo and the stale-
exemption rule could never fire" - the reason SELF is explicitly excluded).
Without that exclusion this test would have shown 0 failures instead of 1.

FORWARD NOTE
Still-open angles on this item per the seventeenth-pass note: ownerOf()'s
prefix-fallback collision risk between brandSlugs has never been directly
injection-tested. Also newly noted this pass: no rule in check-postcodes.js
currently normalises a NARRATIVE_POSTCODES *key* itself before using it as a
lookup into byPostcode() (the keys are hand-typed already in normalised
"XX00 0XX" form) - if a future key were ever typed in lower case or with
double spacing, the "is now a real branches.json postcode" check would fail
to match a live branch's postcode via the raw dictionary key (byPostcode is
keyed by norm()'d values, but the STALE loop uses the literal `pc` string
from Object.keys(NARRATIVE_POSTCODES) without running it through norm()
first) - worth a dedicated pass if it is ever judged worth the (currently
zero, since every existing key is already well-formed) live risk.
