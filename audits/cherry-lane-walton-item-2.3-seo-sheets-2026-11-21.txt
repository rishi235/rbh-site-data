WHAT THE CHECKER DOES (read from tools/check-seo-sheets.js)
------------------------------------------------------------
It discovers every *.md file in modules/service/pages, modules/switch/pages
and modules/branch/pages, parses each into blocks keyed by permalink (the
"SEO" dialect: Page Title / Page Permalink / Page Description) or by slug
(the "INDEX" dialect: SEO title / Page slug / URL / SEO description), then
walks every generated .html page in those three folders and compares:
  - the page's own "Weebly page SEO title" / "Weebly page SEO description"
    head-comment lines against the matching *-SEO.md sheet entry (title
    drift / description drift),
  - the same two page lines against the matching *INDEX.md sheet entry,
    where a row exists,
  - coverage both ways (a page with no sheet entry fails; a sheet entry
    with no matching page fails).
It does NOT read the Meta Keywords line (that belongs to check-seo-keywords.js)
and does NOT read the H1 (that belongs to check-seo-lengths.js rule 3's
sibling work) - this pass's negative control exploits exactly that boundary.
