INFRASTRUCTURE NOTE (not a worklist item, logged for the next run)
--------------------------------------------------------------------
This run's scratch work was built under the sandbox's own native filesystem
(/sessions/.../scratch-3.6-seosheets) rather than under the mounted outputs
folder used by prior passes. Confirmed by direct test: `rm -f` inside the
FUSE-mounted outputs folder fails "Operation not permitted", identically to
the long-documented .git lock behaviour (Q87/Q96/Q102), and this is NOT
limited to the repo's .git directory - the same mount-wide restriction was
found (touch+rm on a plain file under mnt/outputs/scratch-3.6-seosheets
failed the same way) before this pass moved its scratch tree to
/sessions/.../ (native sandbox filesystem, delete confirmed working) for the
rest of the run. Worth carrying forward: any future pass that wants a
restore-by-byte-copy cycle with real deletes between injections should build
its scratch tree under the sandbox's own home/session root, not under either
mounted folder, or it will hit the same accumulate-do-not-delete failure
mode that produced the hundreds of renamed .git/*.lock.* files this run
found already sitting in the repo's .git directory (see AGENT_LOG.md, lock
handling section, this run).
