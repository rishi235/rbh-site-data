THE GAP
ownerOf(relPath) resolves the single branch that owns an OWNED_DIRS file
from its filename. It tries a longest-suffix match on
"<brandSlug>-<townSlug>" first (as check-nap.js does); if that finds
nothing, it falls back to a bare brandSlug PREFIX match, added originally
to cover the two Cherry Lane paste-block replacement files
("cherry-lane-old-pharmacy-first-replacement.html" and
"cherry-lane-old-weight-loss-replacement.html"), whose names do not end in
"<brand>-<town>".

The prefix fallback's old code picked the FIRST branch in branches.json
whose brandSlug prefixed the filename stem, via a ">" (strictly greater)
length comparison that never revisits a tie. Three brand groups share a
brandSlug across two branches each: Scorah (bramhall / hazel_grove),
McCanns (aigburth / sandringham), Fishlocks (ainsdale / eccleston). For any
of those, a filename starting "<brandSlug>-..." but NOT ending in either
sister's own "<brandSlug>-<townSlug>" suffix is genuinely ambiguous - the
filename alone cannot say which sister it belongs to - yet the old code
always resolved it to whichever sister appears first in branches.json
(mccanns_aigburth before mccanns_sandringham; scorah_bramhall before
scorah_hazel; fishlocks_ainsdale before fishlocks_eccleston), silently,
with no warning. This is exactly the "correct by coincidence of array
order, not by rule" shape CLAUDE.md already names for the meta-keywords,
hasApp and map-embed findings (items 3.6, 3.8, 3.9).

No real tracked file hits this path today. Both real files using the
prefix fallback are Cherry Lane's, and Cherry Lane's brandSlug is not
shared with any other branch, so the fallback was never actually ambiguous
in practice. This closes a latent gap, not a live breach.

FIX
tools/check-postcodes.js, ownerOf(): the prefix-fallback loop now collects
every DISTINCT branch matching at the longest brandSlug-prefix length seen.
Exactly one match keeps the old behaviour (returns that branch). Two or
more distinct branches matching at the same longest length now return null
(no owner), which is what already makes checkFile() emit the UNOWNED
warning rule 5 uses for modules/branch/pages/INDEX.md and SEO.md - the
correct "cannot tell" signal instead of a guess.
