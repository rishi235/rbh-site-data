THE FIX, IN tools/check-nap.js ONLY
-----------------------------------
1. unesc() now decodes &nbsp;, &#160; and &#xa0; and normalises a literal
   U+00A0 to an ordinary space, because every sweep in the file splits a fact
   on whitespace.
2. PHONE_RE widened from /\b0\d[\d ]{7,13}\d\b/ to allow the space, hyphen,
   full stop and round brackets between digits, and to accept the +44
   international prefix in place of the leading zero. The real narrowing was
   always the 10-or-11-digit filter and the branch-phone comparison, not the
   regex, so a wider match cannot flag ordinary copy.
3. New phoneDigits() reduces a written number to its national form, turning
   +44 into the leading 0 it stands in for, so the two forms compare equal.
   Used at all three phone sweep sites (generated pages, paste blocks, the
   shared switch template). digits() is left alone: tel: hrefs and JSON-LD
   telephone are machine fields already written one way.
4. The name sweep and the street sweep now match without regard to case.
5. A new FOREIGN POSTCODE, ANY CASE rule. Deliberately narrow: PC_RE was NOT
   given a /i flag, because case-insensitively the postcode shape also fits
   ordinary copy such as "vitamin B12 3rd", and this checker's value is that
   it does not cry wolf. The new rule looks only for a string that IS another
   live branch's postcode, which can never be innocent on this page, and it
   skips an all-upper-case occurrence because the existing sweep reports that
   one already. Stated residual: an unrecognised lower-case postcode-shaped
   string is still not read.
