OBSERVATION, NOT A DEFECT
Test 7 shows the OFFER_PATTERNS "saving claim" pattern
(`/\bsave\s+£?\s?\d/i`) is only reachable in its own right when a saving is
stated WITHOUT a literal £ symbol (e.g. "save 10%" with no "off", or "save
10 points") - because the PRICE_PATTERNS loop runs first for each scope and
its own plain `£\s?\d` pattern matches "save £10" before the OFFER_PATTERNS
loop is reached, and the code `break`s on the first PRICE_PATTERNS hit. The
practical effect is a wrong RULE NAME in the failure message (a price,
not a saving claim) for the single most natural way to write a discounted
price in British pharmacy copy, but not a missed breach: both patterns exist
to enforce the same prohibition (compliance/WEIGHT_LOSS_LIVE_PAGE_ASSESSMENT.md
section 5) and the copy is blocked either way. Recorded for completeness,
in the same spirit as this repo's "ask which files/lines a checker actually
read" convention, but not raised as a question or a fix: unlike the item
4.6 mojibake bug (which caused a genuine silent miss), this is message
attribution only and every tested string is still caught.
