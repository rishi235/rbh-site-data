FRESH ANGLE
No prior pass had tested fitTitle's OWN defensive comparison in
tools/seo-pattern.js:

    function fitTitle(compose, brand) {
      var full = compose(brand);
      if (full.length <= TITLE_WARN_LEN) return full;
      var shorter = shortenBrand(brand);
      if (!shorter) return full;
      var retry = compose(shorter);
      return retry.length < full.length ? retry : full;
    }

Every prior pass on this rescue (Q14/Q24, sixth pass 2026-08-30) tested
whether the rescue fires when it SHOULD. Nothing had tested what happens if
shortenBrand() were ever broken in a way that made things WORSE rather than
better - the `retry.length < full.length` comparison is the only thing
standing between a future regression in shortenBrand() and a title that
silently gets a nonsense suffix appended instead of the brand trimmed. Under
today's shortenBrand() (strips " Pharmacy"/" Chemist"/" Chemists"), retry is
always strictly shorter than full when a shorter exists, so the false branch
of that ternary (`: full`) has never been exercised by real behaviour, and no
pass had proved it actually protects anything.
