Q76 implementation - check-gbp-packs.js branchName rule
Run: audit-backlog-worker, scheduled run 199, 2026-10-14

BACKGROUND
----------
Q76 was raised on the item 4.12 fifth quality pass (2026-08-14): a GBP post
could name a different RBH shop instead of its own, because the trading name
was the one identifying detail in published GBP pack copy with no safeguard,
even though phone numbers, postcodes, review links, street addresses, house
numbers, roads and towns are all already guarded by existing rules in
tools/check-gbp-packs.js. Injecting "the pharmacist-led weight loss clinic at
Cherry Lane Pharmacy in Walton" into Post C of coleman-leigh-walton.md,
replacing the branch's own trading name, passed all checkers clean at the
time. Recheck on 2026-09-28 (run 441, in-repo, unattended) confirmed the gap
was still open against the then-current checker.

Rishi answered via the portal, 2026-10-10 (recorded in the feed 2026-10-11
00:32:38 UK time), choosing option 1 of 4 (the recommended option): add a
rule to check-gbp-packs.js failing any other live branch's branchName in the
published copy (business description and post bodies only - explicitly NOT
the services section, narrower than the existing foreign-town rule), with
the existing sister-claim exemption carried over so mccanns-aigburth.md can
keep naming "a second branch, McCanns Chemist Sandringham" inside its own
description.

This answer sat in QUESTIONS.json as "answered" since the portal pickup but
had not been implemented in the repo by any run between then and run 198
(confirmed by grepping AGENT_LOG.md and git log for "Q76" / "branchName" -
no implementing commit found). Per the established precedent of run 164
(which implemented Q71 when the worklist's 8 unchecked lines were all
[BLOCKED] and no quality-pass checker-injection angle remained for the
rotation-pool item), this run implemented Q76 as its single work item
instead of a further quality pass, since:
  - all 8 unchecked AGENT_WORKLIST.md lines were reconfirmed [BLOCKED]
    (5.3/Q8, 5.4/Q9, 5.5/Q13, 5.8/Q16, 6.1/Q52, both Q60 lines, 6.6/Q66);
  - the rotation-pool item for a quality pass (4.12, stalest at
    2026-09-19T05:16) has had all 35 non-network checkers already proven
    against it by direct injection as of its twentieth pass (2026-09-18),
    so a further quality pass on 4.12 specifically would not exercise a
    genuinely new checker angle;
  - Q76 is a concrete, scoped, answered-but-unimplemented decision that
    improves a real guard rather than re-verifying already-clean work.

WHAT CHANGED
------------
tools/check-gbp-packs.js:
  - new KNOWN_BRANCH_NAME / seenBranchNameKnown exception map (anti-rot
    convention identical to every other KNOWN_* map in this file), added
    immediately after KNOWN_FOREIGN_TOWN;
  - new rule block, inserted immediately after the existing foreign-town
    rule: scans the business description and the post bodies (via the
    existing descriptionOf()/postsOf() helpers) for any other live branch's
    branchName; a sentence-bounded match that is NOT inside a governed
    sister-claim sentence ("sister"/"second" + "branch(es)", the same
    exemption phrase the foreign-town rule already uses) fails; a KNOWN
    exception, if one is ever added, downgrades to WARN;
  - new stale-exemption sweep entry for KNOWN_BRANCH_NAME, mirroring every
    other KNOWN_* sweep in the file.

No pack, generator, page or branches.json content was changed. This is a
checker-only change.
