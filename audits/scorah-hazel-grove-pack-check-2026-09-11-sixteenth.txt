NEW ANGLE, and a real defect found and fixed (in the checker, not the pack)

Every phrase-matching rule in check-gbp-packs.js - MEDICINE_NAMES,
EFFICACY_FAIL, EFFICACY_WARN, CLAIM_PATTERNS, BODY_IMAGE_SELF (all via the
shared findTerms()/findClaims() helpers), and the standalone OUTCOME_PROMISE
loop - read a pack by splitting the raw file into lines with
text.split(/\r?\n/) and testing each line on its own. A pack's markdown
source hard-wraps at roughly 76 columns purely for readability in this repo;
that wrap point carries no sentence or clause meaning. A banned multi-word
phrase that happened to fall across a wrap was therefore invisible to every
one of those rules, although the wrap is not present in what actually
reaches the public: a paster copies the whole post paragraph into Google's
plain-text post field, which does not preserve the source file's line
breaks at all. So the checker's blind spot and the pack's actual published
wording were never the same shape - precisely the class of silent fault this
repo's own history (CLAUDE.md: the map iframe, the phone number, the meta
keywords line) keeps finding in different checkers.

Why BODY_IMAGE_CONTEXT was never vulnerable: it already matches against
postsOf()'s own p.body, which postsOf() keeps as one unsplit string per post
(embedded newlines and all), and its patterns use \s+ rather than being
tested per split line - so a wrap inside a BODY_IMAGE_CONTEXT phrase was
already invisible to the bug that hit BODY_IMAGE_SELF. This is also why the
item 4.14 pass's own estate-wide sweep ("swept across all 16 packs, all 177
generated pages ... ZERO matches anywhere") did not surface this gap: that
sweep ran real copy through both BODY_IMAGE_SELF and BODY_IMAGE_CONTEXT
looking for existing false positives, not synthetic phrases engineered to
straddle a wrap, and only BODY_IMAGE_SELF (and the sibling rules sharing its
line-splitting shape) had the blind spot.

The fix: tools/check-gbp-packs.js

Added a paragraphsOf(text) helper that splits the file into paragraphs
(runs of consecutive non-blank lines, broken at each blank line), joins each
paragraph's wrapped lines back into one logical line with single spaces
(norm()'s own whitespace collapse), and returns { text, startLine } per
paragraph. findTerms() and findClaims() now iterate paragraphs instead of
raw lines; the OUTCOME_PROMISE loop (which could not go through findClaims,
since it also needs the question-exemption sentence-split) was rewritten
the same way, iterating packParas instead of packLines, with the sentence
question-exemption logic unchanged and applied to the joined paragraph text.
Reported line numbers are now a paragraph's own first line rather than
guaranteed to be the exact line a match starts on, which is enough to locate
the paragraph a human would recognise; the joined text is what decides pass
or fail, and that is the part that has to be right.
