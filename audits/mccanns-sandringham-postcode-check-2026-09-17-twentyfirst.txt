FIX (applied to the scratch copy first, then the tracked checker). Split the
named.length handling into three cases: 0 (unchanged, return), 1 (unchanged
logic, same message), and >= 2 (new). For the new case, every postcode found on
the line is checked against the byPostcode[] map; if it resolves to a real, live
branch whose id is NOT in the already-built namedIds set (reused, not recomputed),
that is a misattribution against all the named branches at once. A postcode that
correctly belongs to one of the named branches - "Smartts Chemist (L20 9HH) and
Riddings Pharmacy (WA15 6BP)" - is unaffected, because its owner IS in namedIds.
MISATTRIB_KNOWN is honoured on a key built from the sorted named-id set
(`file::[id1,id2]::postcode`), the same exemption convention as the single-branch
case, in case a genuine multi-branch comparison needs excusing later; none exists
today, so nothing was added to that list.
