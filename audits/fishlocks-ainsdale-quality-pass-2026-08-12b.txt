THE FINDING - A VERIFIER GAP, NOW CLOSED
Nothing verified that a branch's pfLink names a Pharmacy First page that
branch actually owns.

check-branch-links.js tested pfLink two ways: that it sits on the branch's own
website host, and that it ends .html. Both are blind on a shared domain. Three
hosts serve two branches each:
    fishlockpharmacy.co.uk  -> fishlocks_ainsdale, fishlocks_eccleston
    mccannspharmacy.co.uk   -> mccanns_aigburth, mccanns_sandringham
    scorah-chemists.co.uk   -> scorah_bramhall, scorah_hazel
so a pfLink pointing at the sister branch passes the host test, ends .html and
resolves 200. check-branch-identity.js rule 10 does resolve a page name to its
owning branch, but only for links printed on pages; it never reads a data
field. pfLink is a data field.

PROVED BY INJECTION, not asserted. fishlocks_ainsdale.pfLink was swapped to
the Eccleston Pharmacy First page:
  - first run: caught only by check-editor-snapshot.js, which is a drift
    tripwire between branches.json and the embedded editor snapshot. It fires
    on any data edit at all and prescribes refreshing the snapshot.
  - so the snapshot was refreshed and the pages rebuilt, which is the ordinary
    workflow after any data edit: ALL 29 CHECKERS THEN PASSED.
The harm is not cosmetic. pfLink feeds the landing page Pharmacy First route
and the GBP pack Pharmacy First button (check-gbp-packs.js line 818 makes the
pack agree with the data, so a wrong value is faithfully reproduced). On a
shared host the patient is quietly booked into the wrong pharmacy. This is
also the field item 2.1's original audit found stale for both Fishlocks
branches, so it has drifted before.

THE FIX
check-branch-links.js gains a pfLink ownership rule. It resolves the pfLink
filename to its owning branch by the longest brandSlug-townSlug suffix, the
same resolution rule 10 uses, and requires that branch to be the branch
holding the field.

A filename that resolves to no branch is left alone deliberately. Eleven of
the fourteen live pfLink values are still the legacy
"pharmacy-first-service-<town>" names that Q8 / item 5.3 owns, including the
two pre-existing shared-page cases (both Scorahs point at
pharmacy-first-service-hazel-grove-bramhall, both McCanns at
pharmacy-first-service-aigburth). Firing on those would duplicate 5.3 and
break the build over a decision already with Rishi.
