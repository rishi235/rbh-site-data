PART 2 - THE DEFECT: AN EXCEPTION GRANTED FOR VALUES WAS ENFORCED AS A
LICENCE TO BREAK A RULE

check-address-region.js holds one accepted exception, keyed
mccanns_sandringham::townSlug. Rishi granted it under Q15 for one specific
arrangement: townSlug held at "sandringham" while seoTown reads
"St Michael's", so the copy moves and no live URL breaks.

The rule it excuses is "townSlug must be the slug of seoTown". That rule is
broken by EVERY seoTown whose slug is not "sandringham", not just by
St Michael's. The entry was keyed to the rule, so it absorbed all of them.
The file's stale-key guard proves an exception is still USED; nothing proved
it was still the exception that was GRANTED.

PROVED BY INJECTION, NOT ASSERTED. seoTown was moved to "Lark Lane", another
town in this branch's own serviceAreaList, so the seoTownInList rule stays
satisfied and no other branch owns the word. The change was then made the way
an operator would actually make it, in three places:

  1. branches.json                        seoTown -> Lark Lane
  2. tools/build-switch-pages.js          the hardcoded town for this branch
  3. gbp-packs/mccanns-sandringham.md     the catchment run reordered

then a full regeneration of all 177 pages.

The value it read and the value it was granted for are both in that one line.

WHY IT MATTERS. seoTown is the word every title, description, H1, meta
keyword set and areaServed entry on 13 pages leads with, and it is the one
field on this branch that a human decision is on record about. The exception
existed precisely because this branch is the estate's one deliberate
irregularity, which makes it the one place a second irregularity would be
least likely to be noticed.

THE FIX, IN THE VERIFIER, NOT IN THE DATA
tools/check-address-region.js. No page, generator, data field, paste sheet,
GBP pack or piece of patient-facing copy was changed.

  - Every KNOWN_SEO_TOWN entry must now declare an "expect" block naming the
    exact field values the exception was granted for. The one live entry
    declares townSlug "sandringham" and seoTown "St Michael's".
  - A new grantedFor() gates all three consumption sites (seoTownInList,
    areaLead, townSlug). It hands back the exception only while the branch
    still holds those values; otherwise it fails and the ordinary rule
    applies, so the operator gets both the drift message and the underlying
    breach.
  - An entry with no expect block FAILS, so the hole cannot be reopened by
    adding a looser entry later.
  - An expect block naming a field this file does not read FAILS, so an
    expectation cannot be written that is never tested.
  - Comparison goes through the file's existing normalise(), so case and
    apostrophe style are not a false positive. Arrays compare in order.
  - The existing stale-key guard is unchanged and still bites.
